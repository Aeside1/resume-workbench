# 简历工作台领域上下文

本文定义领域词汇、关系和业务边界，为产品、页面和系统设计提供统一语言。

## 术语

**用户（User）**：使用系统管理自己职业经历和简历方案的个人，账号本身即为其唯一的个人职业经历与简历方案工作空间。
_Avoid_：工作区、租户、组织

**经历分组（Experience Group）**：一段完整的实习经历或一个项目经历，是多条具体工作内容的容器，直属于用户账号。

**具体工作内容（Work Content）**：经历分组下的一项具体工作或项目贡献，包含详细记录和补充材料。

> **界面用词说明**：左侧栏第二个入口的整页内容（经历分组、具体工作内容、简历亮点）统称为 **经历资产**；「资产」强调它可被复用与引用，不是通用词，界面文案可统一使用。

**简历亮点（Resume Highlight）**：具体工作内容中提炼出的、可以直接放进简历的描述文本。同一项具体工作内容可以拥有多条简历亮点，代表同一件事的不同写法，并各自支持修订记录。
_Avoid_：简历描述、描述版本、版本卡片、表述

> **界面与文档用词说明**：界面文案、领域文档、领域对象名统一使用 **简历亮点**；`ResumeDescription` 等代码标识符保留旧名，不做机械重命名。

**简历方案（Resume Plan）**：面向一次求职准备、投递或展示用途的一套可编辑简历组合，直属于用户账号。一份简历方案就是「一个岗位方向的一版简历」。
_Avoid_：简历版本、多版本简历

**简历大纲（Resume Outline）**：简历方案的编排结构，包含实习经历与项目经历两个固定**板块**，每个板块下按顺序排布**经历块**，经历块内按顺序排布**简历条目**。

**板块（Section）**：简历大纲的一级分组，固定枚举为 `internship`（实习经历）与 `project`（项目经历），不可自定义。
_Avoid_：模块

**经历块（Plan Experience Group）**：简历大纲中被引用的一段经历分组，由该分组的类型自动决定所属板块，块内承载若干简历条目。

**简历条目（Plan Item）**：简历大纲中的一行，表示「某条具体工作内容下的某条简历亮点」被采纳进本方案，包含所属经历块与排序位置。
_Avoid_：引用、简历条目引用

**方案留档（Plan Archive）**：简历方案在某一时刻的完整内容留档，包含两类来源——结构性变更产生的 `revision`，以及导出动作产生的 `export`。留档创建后不可变。

**导出快照（Export Snapshot）**：方案留档中来源为 `export` 的那一类，保存导出时的完整简历内容和元数据，可附带投递备注。

**简历文稿（Resume Document）**：由简历方案组装出的通用 Markdown 文本。它是工作台与外部简历编辑工具之间的唯一交换格式。

**投递稿（Application Draft）**：用户在简历文稿基础上进一步编辑渲染出的最终投递材料。它**不属于简历方案（简历组合）模块的范围**；其归属（本应用内的独立模块，或应用外的编辑工具）留待后续单独设计，本切片不实现、也不为其保存任何字段。

## 关系

```text
User
├── ExperienceGroup[*]
│   └── WorkContent[*]
│       └── ResumeHighlight（简历亮点）[*]
└── ResumePlan[*]
    ├── PlanExperienceGroup[*]（经历块 -> ExperienceGroup）
    │   └── PlanItem[*]（简历条目 -> WorkContent + ResumeHighlight）
    └── PlanArchive[*]（方案留档：修订 / 导出）
```

## 核心业务边界

- 系统按个人用户账号进行独立数据隔离，用户在系统中维护唯一一份连续完整的过往职业履历资产。
- 经历分组、具体工作内容、简历亮点、简历条目和方案留档是不同对象。
- 针对不同行业或岗位的差异化求职表达，统一通过简历方案（Resume Plan）组合不同的简历亮点实现，不在资产层引入多工作区隔离。
- 编辑简历亮点与具体工作内容的详细记录保持独立。
- 切换简历条目使用的亮点只改变简历方案的引用，不改写资产。
- 移除简历条目只移除引用，具体工作内容和简历亮点继续保留。
- 归档资产不阻断已有引用：方案照常组装输出，只是该资产不再出现在「添加」候选里；彻底删除被引用的资产则被拒绝，并告知引用它的方案。
- 简历方案的预览与简历文稿均为读时装配，不落库；只有方案留档（修订 / 导出）是写时快照。
- 「组合」与「最终投递材料」之间的唯一接口是简历文稿（通用 Markdown）；投递稿的编辑与渲染不属于简历组合模块的职责，其归属（应用内独立模块 / 应用外工具）待后续设计，本切片不实现。
- AI（未来能力）先生成待确认的内容提案，再进入正式内容。

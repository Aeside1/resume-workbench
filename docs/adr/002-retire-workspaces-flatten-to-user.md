# ADR 002: 废除多工作区隔离，领域模型扁平化至用户账号

- **状态（Status）**：Accepted（已确认）
- **日期（Date）**：2026-09-12
- **决策者（Deciders）**：用户 & AI Pair
- **关联文档**：[CONTEXT.md](../../CONTEXT.md)、[ADR 001](001-ui-redesign-workbench-and-focus-canvas.md)

---

## 1. 背景与问题陈述（Context）

在早期的 Alpha 架构设计中，系统引入了“工作区（Workspace）”作为用户数据的容器层级，用户可在顶栏或侧边栏创建并切换多个工作区。

然而在深度推敲与实际使用中发现：
1. **违背个人职业资产的心智模型**：求职者的过往工作履历、实习经历与核心项目是连续且唯一的客观事实集合。求职者不会为了投递不同行业而分裂出多个工作区去重复录入同一段经历。
2. **多版本诉求已由【简历方案（Resume Plan）】承担**：针对不同岗位方向（如全栈、前端、架构师）的差异化表达，天然应由“经历资产库”底部的“多版本简历描述”以及上层的“简历方案”去按需引用组合，而非在资产层强行割裂。
3. **引入不必要的概念复杂度与 UI 冗余**：多工作区是针对企业协作或多租户的过早抽象，强加在个人简历工作台上，不仅造成经历资产人为孤立，还在 UI 黄金位置强行占据了宝贵空间，并引入了“工作区切换”与“新建工作区弹窗”等非核心交互。

## 2. 决策要点（Decisions）

1. **废除 Workspace 概念**：
   - 彻底将“工作区（Workspace）”从领域模型、术语体系和关系拓扑中移除。
   - 用户账号（User）本身即为其唯一的专属个人职业工作台。
2. **实体归属扁平化至 User**：
   - `ExperienceGroup`（经历分组）与 `ResumePlan`（简历方案）的外键直接关联 `user_id`。
   - 所有经历资产对当前登录用户全局可见且唯一累计。
3. **接口与状态极简重构**：
   - 下线所有 `/api/workspaces` 路由。
   - `GET/POST /api/experience-groups` 直接从依赖注入的 `current_user` 获取上下文，移除接口参数中的 `workspace_id`。
   - 前端 `Session` 仅保留 `token` 与 `user`，彻底清理 `workspaces` 数组和 `selectedWorkspaceId`。
4. **UI 侧边栏纯净化**：
   - 左侧侧边栏头部由原先的“工作区下拉切换卡片”重塑为精致的“个人职业工作台 / 用户身份”静态名片（头像 + 用户名称/邮箱）。
   - 释放顶部与侧边栏的交互负担，取消原定工单 `02-create-workspace-modal`。

## 3. 结果与影响（Consequences）

- **收益**：
  - 经历资产实现真正意义上的单点维护与终身沉淀；
  - 全栈代码大幅度精简，消除了大量的参数穿透与冗余的下拉状态处理；
  - 侧边栏与整体 UI 视觉更加聚焦于“经历内容”与“简历方案”两个核心模块。
- **代价与处理**：
  - 需要重构后端表模型（外键切换）与路由；
  - 原定的新建工作区工单 `02-create-workspace-modal.md` 关闭为 `wontfix`。

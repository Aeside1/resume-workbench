# ADR 008: 未登录先入工作台，游客态只读示例内容

- **状态（Status）**：Accepted（已确认）
- **日期（Date）**：2026-10-21
- **决策者（Deciders）**：用户 & AI Pair
- **关联文档**：[CONTEXT.md](../CONTEXT.md)、[ADR 002](002-retire-workspaces-flatten-to-user.md)、[ADR 005](005-resume-plan-reference-model-and-archive-boundary.md)、issue #12

---

## 1. 背景与问题陈述（Context）

当前实现把认证当成整个应用的入口闸门：`frontend/src/App.tsx` 里「有 session 才渲染工作台，否则渲染登录页」，后端 `current_user` 对无令牌请求一律 401。用户提出：

> 改造登录验证，让未登录也能进入工作台查看和简单使用

issue #12 留下四个待明确的问题：未登录能做什么、是否与「账号即工作台」冲突、隐私边界、认证链路现状。

## 2. 决策要点（Decisions）

### 2.1 认证不再是入口闸门

- 没有 session 时直接进入**游客工作台**；认证页降级为按需路由（侧栏底部与游客横幅的「登录 / 注册」，可「先以游客身份继续」返回）。
- 登录后进入账号工作台；退出登录回到游客工作台。

### 2.2 游客态只读前端内置的示例内容

- 经历分组、具体工作内容、简历亮点以**示例内容**呈现，可逐层浏览（列表 → 画布 → 简历亮点抽屉）。
- **不提供任何写操作**：不渲染新建 / 编辑 / 归档 / 删除 / 专注编辑 / 拖拽排序入口。
- **不写浏览器存储**，也不向业务接口发请求；刷新后仍是同一套示例。
- 示例内容以「示例内容 · 只读」横幅标注，避免被误认为真实数据。

### 2.3 简历方案保留为账号能力

简历方案（组合 / 编排 / 文稿 / 留档）依赖账号与服务端，游客态在入口处显示登录引导，不渲染方案列表与创建入口。

### 2.4 与「账号即工作台」的关系

`ADR 002` 的结论不变：账号仍是唯一的服务端工作空间。游客工作台**没有服务端身份**，不是 User、也不是账号内的第二个工作区；它只是前端渲染的一份静态示例，用来展示工作台的结构。

### 2.5 实现方式

- `api` 按 token 分派：已登录走 `httpBackend(token)`，游客态走 `guestBackend`（读示例内容，写操作与方案接口一律拒绝）。页面组件签名不变。
- 只读由外壳下发 `readOnly`：游客态不渲染编辑入口，而不是渲染后再报错。
- 状态切换（登录 / 退出）时整壳重挂，避免把上一个身份的对象带进当前视角。

## 3. 结果与影响（Consequences）

- **收益**：首次访问即可看到工作台的真实结构；零持久化、零跨用户数据面；服务端鉴权口径完全不变（无令牌 401）。
- **代价**：游客无法试用编辑；示例内容的字段结构需要跟随真实模型维护，模型变更时要同步示例。
- **风险**：示例与真实数据可能漂移——用测试锁住示例的父子关系与阅读路径。

## 4. 与既有决策的关系

- **ADR 002（扁平化到 user）**：继续有效，不新增工作区概念。
- **ADR 005（引用模型与留档边界）**：继续有效，方案能力仍只在账号态提供。
- **ADR 003（HeroUI 单一 token 主题）**：横幅与门禁面板只用 HeroUI 组件与语义变量，适配深浅色。

## 5. 验收口径（可测）

1. 无 `resume-session` 首次访问：直接进入游客工作台，出现「示例内容 · 只读」横幅与示例经历分组，不出现登录表单。
2. 经历分组列表与画布不出现新建 / 编辑 / 归档 / 删除 / 专注 / 拖拽入口；简历亮点抽屉不出现新建 / 编辑 / 复制 / 删除。
3. 游客访问「简历方案」：显示登录引导，不请求 `/api/resume-plans`。
4. 游客态不写 `localStorage`，不向 `/api/` 发任何请求。
5. 游客可从侧栏进入认证页，并能「先以游客身份继续」返回；登录后游客横幅消失，读写走服务端。
6. 刷新后仍停留在游客工作台，示例内容不变。

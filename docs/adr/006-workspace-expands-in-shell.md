# ADR 006: 工作区在壳内展开，只有「展开专注」整屏接管

- **状态（Status）**：Accepted（已确认）

## 1. 背景与问题陈述（Context）

[ADR 001](001-ui-redesign-workbench-and-focus-canvas.md) §2.1 定义了「双场景」：Hub（列表）与 **Focus Canvas**，并规定进入某段经历的分组画布时**隐藏侧边栏、顶栏换成面包屑**；[ADR 004](004-zen-focus-shell-as-in-flow-region.md) §2.2/§2.4 进一步把顶栏（面包屑 + 保存态 Chip + 场景动作）明确归给 AppShell。

切片 04 交付简历方案编辑器时沿用了同一形态（进方案即隐藏侧栏）。实际使用中用户指正：

> 【经历内容】和【简历方案】的展开，应该只在右侧工作台展开，不应该覆盖左侧标签栏，目前这两块内容不需要完全的专注模式，只保留【具体工作内容】的【展开专注】全页面覆盖。

也就是说：**「进入某段经历 / 某份方案」不等于「进入专注」**。分组画布与方案编辑器都是日常反复进出的工作界面，用户需要随时切到另一个模块；而真正需要屏蔽干扰的只有「写一条具体工作内容」这件事。同时用户指出编排区不该切到「预览」才看得到内容：

> 不应该切换预览才展示【亮点】中的内容和标题，而且条目的名字应该是【经历分组 + 亮点名称】的组合方式

## 2. 决策要点（Decisions）

### 2.1 外壳只有三种形态，接管整屏的只剩 Zen

| 形态 | 侧边栏 | 顶栏 | 用在哪 |
|---|---|---|---|
| `hub` | 常驻 | 无 | 工作台概览、经历内容列表、简历方案列表 |
| `workspace` | **常驻** | 无 | 分组画布、简历方案编辑器（都在内容区展开） |
| `zen` | 隐藏 | 面包屑 + 保存态 + 场景动作 | 具体工作内容的「展开专注」，**唯一的整屏接管** |

本决策**取代 ADR 001 §2.1 中「画布即第二场景、进入即隐藏侧栏」的部分**；ADR 001 关于「双场景解耦、信息密度克制」的其余结论不受影响。

### 2.2 「返回 / 标题 / 保存态 / 动作」下沉到内容区页头

既然非 Zen 形态没有顶栏，这些元素改由内容区自带的页头（`WorkAreaHeader`）承担：返回上一级（经历内容 / 简历方案）、当前对象标题与副标题、保存态 Chip、场景动作（预览、下载简历文稿）。顶栏因此**只服务 Zen**，ADR 004 §2.2「面包屑与保存态归 AppShell」的适用范围收窄为 Zen 形态。

### 2.3 编排区常驻显示条目正文与组合名

简历方案编辑器里，每条条目直接显示：

- **条目名** = `具体工作内容标题 · 简历亮点名称`（例如「收银台跨端组件重构 · 技术深度版」）——亮点属于具体工作内容，块的抬头已经显示经历分组，因此不在条目名里重复分组名；
- **亮点正文**常驻显示在其下，不再需要切「预览」才看得到。

「预览」因此回归它本来的职责——**检查整体排版与阅读效果**，而不是查看内容的唯一途径。块内的「文稿中打印工作内容标题」开关随之收窄语义：只控制文稿/预览里是否打印工作内容标题，编排区始终显示。

## 3. 决策影响（Consequences）

**正面：**

- 模块导航全程可用，「进分组 → 返回 → 再进另一个分组」不再需要先退出专注；
- 顶栏从「两种形态各有一套」简化为「只有 Zen 有顶栏」，少一套状态与样式分支；
- 编排时能直接读到正文，减少「切预览才发现写错」的往返；条目名自带来源，不必再靠一行小字辨认。

**负面 / 代价：**

- 侧栏常驻后内容区变窄：分组画布的「主画布 + 伴随大纲」与方案编辑器的「编排 + 预览」需要在该宽度下自适配；
- 非 Zen 场景失去顶栏这一层全局状态位（保存态改由内容区页头承担，各视图需要自己接线）；
- 用户可见的导航结构变化，历史截图与文档中的「专注模式」措辞需要按本 ADR 理解。

## 4. 与既有决策的关系

- **ADR 001**：§2.1 中「进入分组画布即接管整屏」的部分被本 ADR 取代；双场景的信息密度原则继续有效。
- **ADR 004**：本 ADR 沿用其「非模态区域展开优于浮层覆盖」的倾向，并把 §2.2/§2.4 的顶栏归属范围收窄为 Zen 形态。
- **ADR 003**：不受影响（视觉与 Token 体系照旧）。

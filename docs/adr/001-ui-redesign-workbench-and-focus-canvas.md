# ADR 001: 工作台双场景与沉浸式经历编写长画布 UI 重构设计

- **状态（Status）**：Accepted（已确认）
- **日期（Date）**：2026-09-12
- **决策者（Deciders）**：用户 & AI Pair
- **关联文档**：[CONTEXT.md](../CONTEXT.md)、[PRD.md](../PRD.md)、[ARCHITECTURE.md](../ARCHITECTURE.md)

## 1. 背景与问题陈述（Context）

在当前 Alpha 原型运行过程中，界面的布局与交互存在以下阻碍深度使用的体验问题：
1. **顶栏空间被过度挤压**：顶栏包含巨大的工作区选择与新建工作区表单，侵占了大量纵向黄金空间。
2. **缺乏沉浸式的深度写作环境**：求职者整理和回忆一段实习或项目经历是一项需要高度专注的“深度工作（Deep Work）”。当前界面在同一屏内混合了导航、列表和底部长表单，页面被边框和输入框切割得较为破碎，无法提供流畅通读与长文本推敲的思考心流。
3. **列表与表单纵向堆叠带来视线断层**：在经历详情中，点击工作内容后表单在页面底部展开，用户需要反复上下滚动，破坏了操作连贯性。

## 2. 决策要点（Decisions）

### 2.1 双场景解耦架构（Two Distinct Modes）

彻底将工作台划分为两个互不干扰的核心使用场景：

```text
【场景 1：全局工作台（Hub Mode）】
   ├── 左侧全局侧边栏：工作区切换、全局导航（概览、经历内容、简历方案）、个人账户
   └── 主内容区：经历内容资产库总览
         ├── 操作栏：[+ 新建经历分组] 按钮、[显示已归档] 开关
         └── 经历分组卡片流（展现经历名称、组织、类型、时间、整体介绍摘要、包含的工作项数量）
               └── 点击卡片 → 平滑切换进入【场景 2】

【场景 2：具体经历沉浸长画布（Deep-Work Focus Canvas Mode）】
   ├── 顶栏：极简面包屑（← 返回经历内容 / [经历名称]）、保存状态（✓ 所有修改已保存）、[退出专注模式] 按钮
   │   （完全隐藏左侧全局侧边栏与主导航，消除所有外界视觉干扰）
   └── 宽屏双区布局（总宽约 1260px，解决宽屏空旷感）：
         ├── 主长画布（宽约 980px）：
         │     ├── 经历整体概况区：组织、类型、时间跨度、整体背景与使命介绍
         │     ├── 具体工作内容卡片流（自上而下顺序排布）：
         │     │     ├── 块级查看态：清晰排版呈现详细工作记录（背景与难点、技术方案、量化结果）
         │     │     ├── 块级编辑态：点击“编辑”就地转为表单控件，带保存/取消
         │     │     └── 简历描述提炼区：挂接多版本简历描述，采用横向 Tab 切换（如 [技术深度版] [业务结果版] [+ 新增写法]），作为内容资产维护，供后续简历方案模块进行引用组合与拼接初版简历
         │     └── 画布底部：常驻虚线按钮 [+ 添加具体工作内容]
         └── 右侧伴随大纲（TOC Mini-map，宽约 240px，吸附常驻）：
               ├── 经历内容大纲清单：经历概况、工作项 1、工作项 2...（随视窗滚动自动高亮当前项，点击平滑滚动直达）
               ├── [+ 新增工作内容] 快捷跳转入口
               └── 底部统计微模块：展示已沉淀工作项与简历描述总数
```

> 注（2026-09-14）：场景 2 内的 **Zen 专注写作子态**不再使用自研全屏覆盖层，形态改由 [ADR 004](004-zen-focus-shell-as-in-flow-region.md) 决定（非模态区域展开）。本 ADR 的双场景架构不变。

### 2.2 信息密度与设计去繁就简（No Overdone Badges）

- 不堆砌过多零散的花哨微标签（不搞 `材料 ✓`、`数据 ✓` 类型的 chip 杂乱堆放）。
- 界面只呈现必要的**经历介绍信息与基本元数据**，将阅读和编辑的重心完全还给“工作记录”与“简历描述”的内容本身。

### 2.3 平台与主题设计规范

- **平台定位**：第一阶段仅面向**电脑桌面端宽屏**（1080p / 2K / 4K），优先做好大屏下的舒适居中画布排版，避免在初始阶段过早陷入复杂的移动端自适应。
- **UI 设计系统**：严格遵循 **HeroUI** 设计规范，提供浅色（Light）与深色（Dark）双主题支持：
  - 浅色主题：以清爽的 Neutral 浅灰阶（`#f8fafc` / `#ffffff`）为底，搭配 1px 微边框与深色高对比文字。
  - 深色主题：以深度锌灰（`#09090b` / `#18181b`）为底，低饱和克制强调色，提供夜间沉浸编写体验。

### 2.4 后续扩展特性的处理原则

- **自由记录（灵感与速记暂存）**：确认作为后置特性，当前阶段不引入正式代码，已登记为待评审需求（内部 issue tracker，不入版本库）。

## 4. 后续实施任务切片（Implementation Roadmap）

在下一阶段正式进入代码重构时，建议按以下清晰边界切分实现：

1. **切片 1（AppShell 侧边栏化）**：将工作区切换与顶层主导航整合为现代全局左侧侧边栏，支持退出专注模式。
2. **切片 2（工作台经历管理页重构）**：将经历分组列表重构为卡片流，新建经历抽离为 HeroUI Modal 弹窗。
3. **切片 3（沉浸式长画布容器实现）**：实现全宽无侧栏的 Focus Mode 容器及顶部轻量面包屑导航。
4. **切片 4（工作内容长画布与块级编辑）**：实现长画布中工作内容自上而下的流式排布、块级阅读态与编辑态切换。
5. **切片 5（简历描述多版本 Tab 挂接）**：在单项工作卡片底部实现多版本 Tab 切换与复制（配合 Issue 03 核心逻辑）。

## 5. 修正说明（2026-09-15，[ADR 006](006-workspace-expands-in-shell.md)）

本 ADR §2.1 的双场景中，**「进入分组画布即接管整屏（隐藏侧栏 + 顶栏换面包屑）」这一部分已被取代**：

- 分组画布与简历方案编辑器改为在 **`workspace` 形态**于内容区展开，**侧边栏常驻**；
- **只有具体工作内容的「展开专注」（Zen）才是唯一的整屏接管**；
- 「返回 / 标题 / 保存态 / 动作」下沉到内容区自带的页头，顶栏只服务 Zen。

§2.2（信息密度与设计去繁就简）、§2.3（平台与主题规范）、§2.4（后续扩展特性处理原则）继续有效。
本 ADR §3 中「场景 2：无侧栏极简顶栏」的视觉示意图按本修正理解（侧栏保留，其余排版结论不变）。

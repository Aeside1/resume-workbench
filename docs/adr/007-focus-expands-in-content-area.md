# ADR 007: 专注写作区在内容区展开（取消「整屏接管」）

- **状态（Status）**：Accepted（已确认）
- **日期（Date）**：2026-09-15
- **决策者（Deciders）**：用户 & AI Pair
- **关联文档**：[ADR 001](001-ui-redesign-workbench-and-focus-canvas.md)、[ADR 004](004-zen-focus-shell-as-in-flow-region.md)、[ADR 006](006-workspace-expands-in-shell.md)、[CONTEXT.md](../CONTEXT.md)

---

## 1. 背景与问题陈述（Context）

ADR 004 把 Zen 从「自研全屏浮层」改成「AppShell 内容区里的一块」，但保留了 **ADR 006 §2.1 的形态表**：`zen` 是唯一整屏接管的形态（隐藏侧栏 + 顶栏面包屑），理由是「真正需要屏蔽干扰的只有写一条具体工作内容这件事」。

侧栏折叠（04h，`.app-sidebar--collapsed`）落地后，这个理由不再成立：**想要宽度的人自己折一下侧栏就行**，而整屏接管会把模块导航整体切断——「写完一条 → 想换分组 / 换方案」必须先退出专注。用户据此提出：

> 专注模式需要调整改动一下，现在侧边栏能够折叠了，我建议【专注模式】也和【具体工作内容】页面打开一样，在右侧工作台界面进行全屏展开就好了，用户有需要折叠左侧栏就好了。

同时，04g 引入内容区页头（`WorkAreaHeader`）时，Zen 形态下仍无条件渲染画布那条「返回经历内容」页头，于是真实浏览器里专注屏幕上有**两条导航行**、保存中会同时出现**两个**保存态 Chip（基线探针实测：`保存态指示器数量峰值：2`，见 §5）。

## 2. 决策要点（Decisions）

### 2.1 外壳只剩两种形态，侧栏在所有形态下常驻

| 形态 | 侧栏 | 页头 | 用在哪 |
|---|---|---|---|
| `hub` | 常驻 | 无 | 工作台概览、经历内容列表、简历方案列表 |
| `workspace` | **常驻** | 内容区自带 | 分组画布、简历方案编辑器、**展开专注的写作区** |

`AppShell` 删除 `zen` 形态与 `isFocusMode`，不再拥有任何页头；「展开专注」只是内容区的一种**高度模式**（`isFocusOpen` → `.app-shell--focus`），不是一个外壳形态。本决策**取代 ADR 006 §2.1 中「zen 是唯一整屏接管」的部分**。

### 2.2 专注页头归内容区，且与画布页头二选一

- 原 AppShell 顶栏的实体搬进 `features/FocusTopbar.tsx`，由 `WorkbenchShell` 在内容区渲染：返回按钮（「返回画布」）+ 三级 `Breadcrumbs`（经历内容 / <分组名> / <工作项标题>）+ 保存态 `Chip` + 右侧动作插槽（Esc 提示、伴随栏开合）；
- **展开专注时页头是「替换」而不是「叠加」**：同一位置要么是画布的 `WorkAreaHeader`，要么是 `FocusTopbar`，一屏只有一条页头、只有一条保存态；
- ADR 004 §2.2/§2.4 关于「顶栏归 AppShell」的归属条款就此改判为「页头归内容区」，但 §2.1「非模态区域展开」、§2.3（长标题截断约定）、§2.4（退出统一走先 flush 再关、命令下行而非直接卸载）的**内容契约全部不变**。

### 2.3 视口高度仍锁在 shell 上，侧栏照常可用

`.app-shell--focus` 保留 ADR 004 §2.1 的做法：`height: 100vh; overflow: hidden`，把「页头以下的剩余高度」整块交给写作区，页面级不滚动、滚动发生在区域内部（写作区 `ScrollShadow`）。页头因此常驻可见（保存态 Chip 出现时不会被滚走，归零口径仍由 `useTransientSaveStatus` 的 2.5s 承担）。侧栏是 `position: sticky; height: 100vh` 的既有实现，在这一形态下原样成立。

### 2.4 侧栏不自动折叠

进入专注**不**自动收起侧栏，也不改写折叠偏好；用户要更宽就自己折（04h 的「收起侧栏」在专注全程可用）。折叠与专注互不影响：折叠只改变内容区宽度，不会退出专注。

### 2.5 退出路径全部落盘（含两条「直接卸载」的）

ADR 004 §2.4 的「命令下行（`exitSignal`）而非直接卸载」仍适用于 Esc、页头返回按钮、面包屑中间级三条（先 flush 再关）。但侧栏常驻后，**面包屑第 1 级「经历内容」**与**侧栏模块导航**是直接卸载写作区的路径，它们不同「先 flush 再关」链路：因此写作区自身的卸载清理由「只清防抖定时器」改为**先 `flushSave()` 再卸载**（04k，`ZenFocusEditor` 的 `flushSaveRef`）。这样「所有离开路径都落盘」才是真的成立，而不只是三条命令行下行。

### 2.6 展开专注的入场动画（04l）

点「展开专注」时，内容区页头（`FocusTopbar`）与写作区用**同一份参数**一起入场（`useFocusEnterMotion`：0.22s、`cubic-bezier(0.16, 1, 0.3, 1)`、自下方 10px 升起，只改 transform/opacity），不再硬切。

- **只做入场**：退出要「先 flush 保存再关 + 恢复原卡片滚动位置」（§2.5），让写作区为动画多挂 200ms 会和这两件事抢时间，因此退出保持瞬时；
- **减少动态效果**：`prefers-reduced-motion: reduce` 下不播动画，直接落位。这里直接读媒体查询并用 `useSyncExternalStore` 订阅，而不是用 framer 的 `useReducedMotion`——后者只在**调用组件首次渲染**时读一次，而 `FocusCanvasContainer` 是长驻组件（展开专注前后都在），系统偏好中途改变后它会一直用旧值（真实浏览器复测抳到过这个差异）；
- 全局统一开关（`MotionConfig`，可一并覆盖伴随栏滑入、视图切换等其它动效）是另一个决策，不在 04l 范围内。

## 3. 决策影响（Consequences）

**正面：**

- 模块导航在写作全程可用，「写完一条 → 换分组 / 换方案」不再需要先退出专注；
- 一屏只有一条页头、一条保存态，修掉 04g 遗留的重复导航（基线实测两个 Chip → 现在一个）；
- 外壳少一个形态、少一整套「隐藏侧栏 + 顶栏接管」的样式分支；
- 专注区宽度变成用户可调（240px 侧栏 / 76px 图标态 / 折叠后 1364px），比「整屏接管」多一档选择。

**负面 / 代价：**

- **放弃「进入另一个空间」的空间感**：这是 ADR 004 已承认的代价，本次进一步放弃「连导航一起消失」的最后一层隔离感；浅色模式下专注更像「工作台里的一页文档」；
- 内容区宽度受侧栏影响（默认 1440 视口下写作区宽 1200px），需要在该宽度下自适配；
- 「专注」这个名字的语义收窄为「减少内容区里其它内容的干扰」，不再意味着「整屏」。

## 4. 与既有决策的关系

- **ADR 006**：§2.1 的形态表被本 ADR 取代（`zen` 行删除，专注并入 `workspace`）；§2.2「返回 / 标题 / 保存态 / 动作下沉到内容区页头」的结论被**沿用并扩展到专注**。
- **ADR 004**：§2.1 非模态区域展开（锁视口 + 区域内部滚动）沿用；§2.2/§2.4 的顶栏归属改判为内容区页头；§2.3 面包屑截断约定、§2.4 退出路径约定不变。
- **ADR 003**：不受影响（视觉与 Token 体系照旧，`FocusTopbar` 仍只用 HeroUI 的 `Button` / `Breadcrumbs` / `Chip`）。
- **04h**：侧栏折叠的既有结论不变；仅「展开专注时不渲染侧栏」这一条被本 ADR 推翻（当时正是为了让 Zen 独占整屏）。

## 6. 遗留

- 顶栏原有的「经历内容」一级面包屑在侧栏常驻后略有冗余（侧栏「经历内容」导航同样能退出并带脏检查），本次按「保留既有契约、最小改动」不动；若要精简，需另开一票并同步改面包屑断言。
- 专注页头贴着内容区顶边（`app-main--focus` 无内边距），而画布页头有 24px 上边距，两者相互切换时整块内容会上/下移 24px；本次按「页头是一条通栏」的排版保留，是否对齐留待后续视觉细节票评估。
- 窄屏（<1280）仍未自动折叠侧栏（04h 遗留），专注态在此宽度下的写作区会更窄。
- 保存**在途**时卸载写作区（§2.5 的兜底 flush 会被 `isSavingRef` 短路），在途那段请求返回前新敲的字仍会丢——改动前同样如此，不是本次回归；真要收紧需要把「保存队列化」单独设计一票。
